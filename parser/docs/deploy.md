# Як завантажити дані FIRMS і зібрати базу

Ця інструкція для того, хто на новій машині хоче зібрати власну базу FIRMS для застосунку: для однієї країни,
кількох країн або всього світу. Кроки йдуть по порядку: код, дані NASA, множники гармонізації, пакет дампу,
розгортання пакета, перемикання застосунку. Біля кожного кроку стоять виміряні час і розмір.

Готовий тестовий пакет України вже лежить у [../testdata/test-ukraine/](../testdata/test-ukraine/). Щоб
працювати лише з ним, досить кроків 7 і 8.

Усі команди нижче виконуються в теці `parser/`, якщо не сказано інше.

## Що потрібно

- Linux. Скрипти перевіряли лише в Linux.
- Python 3.11 або новіший з numpy (`pip install numpy`). Інших пакетів скрипти не потребують.
- Docker, щоб розгорнути пакет у базу.
- Ключ FIRMS MAP_KEY для кроку 3. Його дають безплатно на сторінці
  https://firms.modaps.eosdis.nasa.gov/api/map_key/.
- Вільне місце на диску:

  | Що | Розмір |
  |---|---|
  | Річні архіви, `data/raw/archive/` | ≈9.1 ГБ |
  | Поточний рік з API, `data/raw/api/` | ≈2.7 ГБ на 2026-11-14 |
  | Множники з кешем підрахунків, `data/harmonization/` | ≈1.1 ГБ |
  | Пакет України | 62 МБ, база з нього ≈0.9 ГБ |
  | Пакет світу | ≈10 ГБ (оцінка), база з нього ≈50–60 ГБ (оцінка) |

Тека `data/` не йде в git: її ігнорує `parser/.gitignore`.

## 1. Код

Скрипти лежать у гілці `dev` репозиторію застосунку:

```bash
git clone -b dev https://github.com/vmexanik/2026-NASA-Space-Apps-Challenge.git
cd 2026-NASA-Space-Apps-Challenge/parser
python3 -m unittest tests.test_firms tests.test_firmsdb tests.test_firmsdb_sources tests.test_firmsdb_export tests.test_harmonize
```

Тести проходять за ≈20 секунд і не потребують ні мережі, ні даних FIRMS. Тести SQL
(`python3 -m unittest tests.test_firmsdb_sql`) самі запускають і прибирають контейнер `postgis/postgis:17-3.5`,
тому потребують Docker.

## 2. Річні архіви FIRMS

```bash
python3 fetch_archive.py
```

Скрипт завантажує річні архіви всього світу в `data/raw/archive/`: MODIS від 2000 року, VIIRS Suomi NPP від
2012 року і VIIRS NOAA-20 від 2018 року, кожен до минулого року. MAP_KEY для цього не потрібен. Виходить 48 zip,
≈9.1 ГБ. 2026-11-14 завантаження тривало ≈7 годин: сервер FIRMS дає ≈0.1 МБ/с на одне з'єднання.

Якщо завантаження перервалося, та сама команда продовжує його: файли, завантажені повністю, скрипт пропускає.

## 3. Поточний рік з API FIRMS

Річні архіви закінчуються минулим роком, тому поточний рік береться з API FIRMS. Для цього потрібен ключ у файлі
`parser/.env`:

```
FIRMS_MAP_KEY=<ваш ключ>
```

Потім:

```bash
python3 fetch_current_year.py
```

Скрипт завантажує поточний рік для всього світу в `data/raw/api/<джерело>/`, по одному файлу CSV на 5 днів.
2026-11-14 це зайняло ≈1.5 години (191 запит) і дало ≈2.7 ГБ. Коли ліміт ключа закінчується, скрипт сам чекає,
поки ліміт відновиться. Перерваний запуск продовжує та сама команда.

## 4. Множники гармонізації

`build_factors.py` рахує множники, які перетворюють точки MODIS на точки VIIRS Suomi NPP, по одному на квадрат
2° і календарний місяць. Він пише файли версії методу, які бере пакет дампу. Йому потрібні дані FIRMS на диску, у
такому порядку:

1. Річні архіви світу в `data/raw/archive/` (крок 2): MODIS від 2000 року, VIIRS Suomi NPP від 2012 року і
   VIIRS NOAA-20 від 2018 року, кожен до минулого року.
2. Поточний рік з API FIRMS у `data/raw/api/<джерело>/` (крок 3). Для нього потрібен `FIRMS_MAP_KEY` у `.env`.
3. Самі множники:

   ```bash
   python3 build_factors.py --version v1-2026-11-14
   ```

   Файли пишуться в `data/harmonization/v1-2026-11-14/`: `method.json`, `method_weight.csv`,
   `method_factor.csv`, `method_error.csv`, `method_gap.csv`, а перевірка — у `report.html` і `report.json`.
   Команда не замінює наявну версію без прапорця `--force`. Підрахунки кешуються в `data/harmonization/.cache/`,
   тому другий запуск з іншими параметрами (наприклад, `--lambda`) не читає архіви знову.

Команді потрібен кожен річний архів до `--last-year` (типово — минулий рік, як їх завантажує
`fetch_archive.py`). Множники вчаться на MODIS і Suomi NPP 2012–2022, похибка NOAA-20 — на NOAA-20 і Suomi NPP
2018–2025, а запасні дні й неповні місяці потребують кожного року ряду. Якщо якогось архіву нема, команда
зупиняється з кодом 2 і списком файлів, яких бракує. Якщо нема файлів поточного року в `data/raw/api/`, вона лише
попереджає: тоді дні після останнього річного архіву лишаються без супутника.

Без цього кроку пакет матиме лише версію `v0-raw`, тобто числа без гармонізації.

## 5. Пакет дампу

Пакет — це тека з файлами SQL схеми, стиснутими даними, `manifest.json`, `README.md` і `restore.sh`. Пакет
будується просто із сирих файлів `data/raw/`, база для цього не потрібна.

Пакет для вибраних країн:

```bash
python3 export_dump.py --out data/dump/<назва> --countries Ukraine,Brazil,Australia \
    --method v0-raw --method v1-2026-11-14 --jobs 8
```

- `--countries` приймає англійські назви країн через кому, так, як їх пишуть файли в zip FIRMS: `Ukraine`,
  `Brazil`, `Australia`, `Russian_Federation`. Усі 208 назв показує команда
  `unzip -Z1 data/raw/archive/modis_2024_all_countries.zip`.
- `--method` повторюється для кожної версії методу: `v0-raw` або назва теки з кроку 4 у `data/harmonization/`.
- `--years 2020-2026` бере лише точки цих років.

Пакет країн бере з архівів лише файли цих країн. У файлах API країн нема, тому з них пакет бере точки клітинок
0.25°, у яких є архівні точки цих країн. Отже, у прикордонних клітинках пакет містить і точки API сусідніх
країн.

Пакет світу будується без `--countries`:

```bash
python3 export_dump.py --out data/dump/world --method v0-raw --method v1-2026-11-14 --jobs 8
```

Пакет світу важить ≈10 ГБ і збирається ≈12 хвилин з `--jobs 8`. Обидва числа — оцінка. Кожен процес тримає в
пам'яті рядки одного річного zip: до ≈2 ГБ для zip VIIRS усього світу. Отже, `--jobs 8` потребує ≈16 ГБ
оперативної пам'яті.

Тестовий пакет України будує одна команда:

```bash
./make_test_dump.sh --jobs 8 --method v0-raw --method v1-2026-11-14
```

Він пишеться в `data/dump/test-ukraine/`. Пакет України займає 62 МБ і збирається за 46 секунд.

Ті самі сирі файли дають ті самі файли даних. Повторний запуск у ту саму теку `--out` замінює старий пакет.
Непорожню теку без `manifest.json` експортер не чіпає і зупиняється з помилкою.

### Перенесення сирих файлів на іншу машину

Якщо `data/raw/` копіюється з іншої машини, а не завантажується знову, файли мають зберегти час зміни:

```bash
rsync -a <звідки>/data/raw/ data/raw/
```

або `cp -rp`. Файли API за ті самі дні перекриваються, і пакет бере точки з новішого файлу NRT за часом його
зміни. Копія без збереження часу зміни може вибрати старіший файл.

## 6. Перенесення пакета

Пакет переноситься на машину з застосунком як звичайна тека, наприклад:

```bash
rsync -a data/dump/<назва>/ <сервер>:/srv/firms-dump/<назва>/
```

## 7. Розгортання пакета

### У базу застосунку

Як розгорнути пакет у контейнер бази застосунку (`wc_db`), сказано в розділі 1
[docs/database/README.md](../../docs/database/README.md#1-звідки-береться-база). Міграції й сідер Laravel мають
відпрацювати до `restore.sh`.

### В окремий контейнер

Пакет можна перевірити й в окремому контейнері PostGIS, без застосунку. Команди з кореня теки `parser/`:

```bash
docker run -d --name firms-test -e POSTGRES_PASSWORD=secret -p 55440:5432 postgis/postgis:17-3.5
until docker exec firms-test pg_isready -q -h 127.0.0.1 -U postgres; do sleep 1; done
docker cp data/dump/<назва>/. firms-test:/tmp/firms-dump
docker exec firms-test bash -c 'cd /tmp/firms-dump && PGHOST=127.0.0.1 PGUSER=postgres PGPASSWORD=secret PGDATABASE=postgres ./restore.sh --jobs 4'
```

- Друга команда чекає, поки запуститься сервер. Спершу образ запускає тимчасовий сервер лише на сокеті, щоб
  увімкнути PostGIS. Тому готовність перевіряється через TCP, і `restore.sh` теж підключається через TCP.
- Третя команда копіює вміст теки пакета, а не саму теку. Для готового тестового пакета замість
  `data/dump/<назва>` треба підставити `testdata/test-ukraine`.

Наприкінці `restore.sh` пише `OK`: кількість рядків у базі збіглася з `manifest.json`. Пакет України
розгортається за ≈20 секунд, після нього база займає ≈0.9 ГБ. Пакет світу розгортається ≈1.5–3 години
(оцінка). Прапорці `--jobs` і `--only-year` описує `./restore.sh --help`.

Підключитися до бази в контейнері можна командою `docker exec -it firms-test psql -U postgres`, а з машини —
за адресою `postgresql://postgres:secret@127.0.0.1:55440/postgres`. Контейнер видаляє команда
`docker rm -f -v firms-test`.

## 8. Перемикання застосунку на базу

- У `.env` застосунку: `WE_CHARGE_DATA_DRIVER=postgis`.
- В адмінці на сторінці Settings у полі «Active harmonization method version» (`harmonization_method_version`)
  треба поставити версію, яка є в пакеті, наприклад `v1-2026-11-14`.

Що ще змінюється в застосунку, описано в розділі 2 [docs/database/README.md](../../docs/database/README.md#2-як-перемкнути-застосунок-на-базу).

Готово, коли `restore.sh` пише `OK`, а `/api/meta` показує `demo: false`.
