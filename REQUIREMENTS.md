# Вимоги: Harmonization of MODIS and VIIRS Hot Spots

NASA Space Apps 2026 · складність Intermediate/Advanced · теми: Earth Science, Software
Джерело: https://www.spaceappschallenge.org/2026/challenges/modis-and-viirs-hot-spots/

## 1. Суть завдання

Побудувати **веб-застосунок**, що гармонізує записи hotspot-ів MODIS (2000–донині, Terra/Aqua, добігають кінця життя) і VIIRS (2012–донині, детальніші) у **єдиний часовий ряд** і показує **календар активності горіння** для обраної території.

Проблема: MODIS і VIIRS мають різну просторову роздільність (≈1 км vs 375 м), чутливість і розклад прольотів, тому їх не можна порівнювати напряму.

Цільові користувачі: служби раннього попередження та екстреного реагування, науковці, землекористувачі, пожежники.

## 2. Дані

- Єдине офіційно назване джерело: **NASA FIRMS** (Earthdata). Вкладка Resources на момент аналізу містить лише його; організатори пишуть, що ресурси можуть додати до хакатону, тож перевірити ще раз.
- Потрібні продукти: MODIS (архів, `MODIS_SP`) та VIIRS (S-NPP, за бажанням NOAA-20/21, `*_SP`; для актуальності `*_NRT`).
- Правила: NASA не відповідає за сторонні сайти, потрібно дотримуватись умов використання даних кожного джерела.

## 3. Функціональні вимоги

### Частина 1 — гармонізація (обов'язкова ідея завдання)
- FR-1. Завантаження та нормалізація MODIS і VIIRS до спільної схеми (дата, координати, сенсор, confidence, FRP, день/ніч).
- FR-2. Метод гармонізації, після якого «сенсор походження більше не має значення»: безперервний ряд кількості hotspot-ів з 2000-х до сьогодні.
- FR-3. Документований і відтворюваний метод (припущення, період перекриття, калібрування, обмеження). Журі це цінуватиме більше, ніж сам UI.

### Частина 2 — веб-застосунок
- FR-4. **Вибір області інтересу (AOI)**: малювання на карті та/або введення широти/довготи.
- FR-5. **Вибір діапазону дат.**
- FR-6. **Календар активності горіння**: кількість hotspot-ів по місяцях і роках (з 2000-х), кольорова шкала для порівняння місяців.
- FR-7. Відповіді на питання менеджерів: які місяці й роки мали найбільше пожеж; як поточний місяць порівнюється з **історичною медіаною** для AOI.
- FR-8. Аналітика та візуалізації: аномалії відносно багаторічних середніх, кількість виявлених пожеж, ключові індекси.
- FR-9. **Завантаження CSV** hotspot-ів за результатом пошуку; також експорт аналітики та візуалізацій.

## 4. Нефункціональні вимоги
- NFR-1. Доступні (accessible) кольорові шкали: безпечні для дальтоніків, достатній контраст, не лише колір як носій інформації.
- NFR-2. Інтерактивність (карта, швидкий відгук на зміну AOI/дат): запити по багатолітніх даних мають бути агреговані наперед.
- NFR-3. Зрозумілий інтерфейс для нетехнічних користувачів (оперативники, пожежники).
- NFR-4. Прозорість: показувати, який сенсор/метод стоїть за числом, і що дані гармонізовані.

## 5. Орієнтири для оцінювання (за текстом завдання)
- Чи справді усунено розрив між сенсорами (єдиний ряд).
- Корисність для рішень: календар, порівняння з медіаною, аномалії.
- Інтерактивність і доступність.
- Експорт даних (CSV).

## 6. Пропозиція технічного підходу (моя, не з завдання)

1. **Парсер** (`parser/`, Python): тягне FIRMS (API з MAP_KEY або архівні CSV) → нормалізує → кладе в БД.
2. **Гармонізація**: агрегувати в просторову сітку (напр. 0.25°–0.5°) × місяць; на періоді перекриття MODIS/VIIRS (2012+) оцінити коефіцієнти переходу (відношення/регресія/квантильне зіставлення, окремо для регіонів чи біомів); застосувати до MODIS-ряду до 2012 року. Додатково розглянути фільтр за confidence і порівняння за FRP.
3. **БД**: попередньо агреговані таблиці (клітинка × місяць × сенсор × скоригована кількість) + сирі точки для CSV. PostGIS зручніший для AOI-запитів (див. розбіжність README і docker-compose).
4. **API** (Laravel): AOI (полігон/bbox) + дати → календарна матриця, медіана, аномалія, CSV.
5. **SPA**: карта з малюванням AOI, календарна теплокарта (місяць × рік), графіки аномалій, кнопка «Завантажити CSV».

## 7. Відкриті питання
- Охоплення: весь світ чи окремі регіони (впливає на обсяг даних і час завантаження).
- Чи включати NOAA-20/21 VIIRS, чи лише S-NPP.
- Метод гармонізації: простий коефіцієнт чи складніше. Залежить від часу хакатону.
- Мова інтерфейсу (укр/англ).
- MAP_KEY для FIRMS API.
